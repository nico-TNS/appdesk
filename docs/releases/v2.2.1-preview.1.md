Fix Office installation after removing a suite while retaining standalone OneNote.

Previously, any Click-to-Run product ID was treated as another Office suite. After a successful removal of Microsoft 365 Personal/Family, the remaining `OneNoteFreeRetail` caused AppDesk to reject installation of the chosen new edition before calling Microsoft's installer.

AppDesk now distinguishes Office suites from standalone OneNote, Visio and Project. A standalone product no longer triggers AppDesk's “another suite already present” guard. An existing different suite and incompatible 32-bit installation remain protected.

**Office Removal now includes standalone OneNote** alongside the installed suite and lists both in the separate confirmation. It also supports cleaning up OneNote when it is the only remaining Office product. Visio and Project remain excluded. No notebooks or personal documents are explicitly deleted; users should synchronize or back up notebooks before removal.

Microsoft does not support `OneNoteFreeRetail` alongside volume-licensed Office. If a user installs LTSC without first running Office Removal, a separate No-default confirmation offers to replace standalone OneNote with the OneNote included in LTSC. Only a confirmed replacement adds a targeted OneNote removal to the installation XML; no other standalone product is removed automatically.

Regression tests cover OneNote-only, standalone combinations, same-suite keep/update, different-suite conflict and architecture mismatch. The development PC's actual post-removal configuration was checked without installing another Office edition.

The previous dedicated removal session completed with Microsoft exit code 0, and the remaining registry product was standalone OneNote. The new suite installation itself has not been validated end to end.

**Unsigned preview.** Automatic publisher downloads, the separate Office removal action and the integrated final report remain available.
